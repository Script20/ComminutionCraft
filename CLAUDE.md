# ComminutionCraft

Minecraft Java tech mod focused on ore processing / ore doubling, built in tiers.

## Environment
- Minecraft **26.1.2**, NeoForge **26.1.2.124**, ModDevGradle, Java 25
- Package / group: `com.script.comminutioncraft`, mod id `comminutioncraft`
- JEI is on the classpath (`jei_version` in gradle.properties; compileOnly API + localRuntime)
- IDE: IntelliJ on Windows. Run configs: Client, Server, Data, GameTestServer
- On this machine `JAVA_HOME` points at Java 8, which Gradle can't run on. From a shell, set
  `JAVA_HOME=C:\Users\Script\.jdks\temurin-25.0.5` before `gradlew.bat` (IntelliJ picks its own JDK).
- License: **MIT** (`LICENSE`, `mod_license` in gradle.properties; the jar ships it as `LICENSE_comminutioncraft`).
  `TEMPLATE_LICENSE.txt` is the NeoForge MDK's own MIT notice for the template files.
- 26.1 is unobfuscated and renamed/reworked many APIs (e.g. `Identifier` not `ResourceLocation`,
  `GuiGraphicsExtractor` / `extractBackground` for screens, `ValueInput`/`ValueOutput` for saving,
  `ItemStackTemplate`, `RecipeSerializer` is constructed with `new RecipeSerializer<>(codec, streamCodec)`).
  Don't trust 1.21.x tutorials — check NeoForge 26.1 source/tests or a 26.1 mod (Mekanism `26.1` branch) when unsure.

## Workflow
- After changing datagen code: run **Data** (`gradlew runData`), then Client.
- Generated resources live in `src/generated/resources` — never hand-edit them, change the providers.
- `src/main/resources` should only hold textures (+ `.mcmeta`), and anything that isn't datagen'd.
- Always build/run to verify changes; test on a dedicated server occasionally (`runServer`).

## Code layout
- `registry/` – DeferredRegisters: ModBlocks, ModItems, ModBlockEntities, ModMenus, ModRecipes, ModCreativeTabs
- `machine/` – shared tier-1 machine logic: `FuelMachineBlock`, `FuelMachineBlockEntity`, `FuelMachineMenu`,
  plus `CoalGranulator*` / `CoalSmelter*` subclasses
- `recipe/` – `GranulatingRecipe` (type `comminutioncraft:granulating`, ingredient → result stack)
- `client/` – `FuelMachineScreen` + per-machine screen subclasses (register with `Screen::new`; lambdas fail type inference)
- `data/` – datagen providers. **`ProcessedMetal.ALL` is the single list of metals**: adding one generates its
  granulating, smelting and blasting recipes, `c:dusts/<metal>` tag, item model and lang entry
  (still register the item in ModItems + add a texture)
- Entrypoints: `ComminutionCraft` (common) and `ComminutionCraftClient` (`dist = CLIENT`, screens + datagen).
  Event listeners are registered with `modEventBus.addListener(...)` everywhere — keep it consistent.
- Hoppers/pipes: machines are `WorldlyContainer`s exposed via `WorldlyContainerWrapper` (top = input, sides = fuel, bottom = output)

## Design decisions
### Tier 1 (coal) machines — burn any furnace fuel
| Machine | Job | Speed | Fuel |
|---|---|---|---|
| Coal Granulator | raw ore (`#c:raw_materials/<metal>`) → 2 granulated ore. No ore blocks (reserved for later tiers) | 150 ticks (33% faster than furnace) | normal burn time → 10.67 ops/coal (33% more efficient) |
| Coal Smelter | any vanilla smelting recipe | 100 ticks (2× furnace) | burn time × 0.625 → 10 items/coal |
Tuning constants: `PROCESS_TIME` / `BURN_TIME_MULTIPLIER` in each block entity. Items per coal = 1600 × multiplier ÷ process time.
- Machines store finished recipes (`recipes_used`) and pay out cooking-recipe XP like a vanilla furnace:
  when a player takes from the output slot, or when the block is broken. Granulating recipes give no XP.
- Granulated ores: iron, copper, gold; tagged `c:dusts/<metal>`; smelt in furnace (200t), blast furnace (100t) or Coal Smelter.
- Later tiers add more doubling/tripling (ore blocks, washing, etc.). Tier 2 = electric.

### Texture style: "Dark Chassis" (Mekanism-inspired, original)
- Charcoal casing, smooth gradients (no noise), rounded frame, glowing seam lines in the **tier colour**.
- **Front = top half shows what the machine does, bottom half shows the tier**:
  - Granulator top: sideways roller over a conveyor (chunks in → grit out). Smelter top: conveyor under a heating element (grit in → ingots out).
  - Coal tier bottom: fire door with glowing window + embers. Tier 2 (electric) bottom: blue battery meter.
- Tier colours: coal = orange (`#FF9628`), electric = blue (`#40C4FF`). Seams on front/side/top use the tier colour.
- Machine textures follow vanilla furnace naming: `<block>_top`, `_side`, `_front`, `_front_on` (8-frame animation, frametime 2).
- Block textures are generated by `tools/dark_chassis_system.py` (+ `tools/mekstyle_lib.py`); variant C was chosen.
- GUI sheets are generated by `tools/gui_dark_chassis.py` (writes straight into `textures/gui/container`):
  charcoal panel, recessed slots, orange-rimmed output slot; granulator arrow = segmented orange, smelter arrow = molten.
  `FuelMachineScreen` draws the title seams (glow while lit) and the groove after "Inventory" in code.
- `tools/gen_textures.py` is the old light/stone style — don't run it, it overwrites the Dark Chassis textures.
- The tools need Pillow (`pip install pillow`).
